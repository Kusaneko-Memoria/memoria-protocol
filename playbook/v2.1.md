# Memoria v2.1 (Two-Device) Playbook
## “Witness Requires Another Device”

---

## Goal

Prove, as a hands-on experience, that **meaning is not created at commit-time**.
Meaning emerges **only when a separate, independent witness** references an earlier action.

This version is intentionally minimal:

- No servers
- No accounts
- No blockchain

Just **two devices** and an **append-only ledger** you can copy & paste.

---

## 0) What v2.1 Demonstrates (One Sentence)

**An ACTION is free to exist, but it becomes meaningful only if another device later attaches RESONANCE referencing it.**

---

## 1) Core Rules (Non-Negotiable)

### Rule A — Append-Only Ledger

- The ledger is a list of transactions (TX).
- You never edit past TXs.
- You only append new TXs.

---

### Rule B — No Free Resonance

- A RESONANCE TX must include `ref`, referencing an existing ACTION id.
- If no ACTION exists, RESONANCE is not allowed.

---

### Rule C — Separate Witness (Two Devices)

- Device A commits ACTION.
- Device B attaches RESONANCE.
- Independent witnesshood is required:
  - not the same tab
  - not the same device

---

## 2) Roles & Devices

### Device A — Actor

- You create actions.
- You do not decide their meaning.

### Device B — Witness

- You reference past actions.
- You do not rewrite the action.
- You attach resonance only after the fact.

---

## 3) Data Model (Minimal TX Format)

All TXs share:

    type: "ACTION" | "RESONANCE" | "GENESIS"
    id: unique identifier string
    turn: integer (toy time)
    ts: ISO-8601 timestamp
    note: free text

### ACTION TX

    type: "ACTION"
    id: "action-id"
    turn: 1
    ts: "2026-01-01T00:00:00Z"
    note: "something happened"

Meaning:

- ACTION = “event exists”

---

### RESONANCE TX

    type: "RESONANCE"
    id: "resonance-id"
    ref: "action-id"
    turn: 3
    ts: "2026-01-01T00:01:30Z"
    note: "someone pointed at it later"

Meaning:

- RESONANCE = “someone later referenced this event”

---

### Interpretation

- ACTION is permissionless
- RESONANCE is post-hoc
- Meaning is the **existence of references over time**

---

## 4) UX Requirements (So People Don’t Get Lost)

The app must provide:

- Commit ACTION button (Actor)
- Attach RESONANCE button (Witness)
- Export Ledger (copy-to-clipboard)
- Import Ledger (paste-from-clipboard)

### Required Log Messages

- After ACTION:
  “Meaning undecided.”

- After RESONANCE:
  “Witness referenced ACTION …”

### Ledger View Must Show

    [ACTION]    id=...
    [RESONANCE] ref=...

---

### Strongly Recommended Hints

- If no actions exist:
  “Commit an action first.”

- If actions exist but no resonance:
  “Export to another device and witness it.”

---

## 5) Canonical Demo Flow (2–3 Minutes)

### Step 1 — Device A (Actor)

1. Open v2.1 page
2. Click Commit ACTION (1–3 times)
3. Click Export Ledger

Expected feeling:
- You acted
- Nothing is confirmed
- Ledger contains ACTION TXs only

---

### Step 2 — Transfer Ledger

Send exported ledger text via:
- QR code
- Messenger
- Email
- Copy & paste

---

### Step 3 — Device B (Witness)

1. Open v2.1 page
2. Import ledger
3. Click Attach RESONANCE
4. Export ledger again

Expected feeling:
- Meaning is attached after the fact
- Ledger now contains RESONANCE referencing ACTION

---

### Step 4 — Return to Device A

1. Import witness ledger
2. Observe your earlier action now has a trail

This is the **post-hoc meaning moment**.

---

## 6) What Counts as “Meaning” in v2.1?

v2.1 does NOT:
- Rank
- Score
- Finalize

It demonstrates only this primitive:

- Meaning is not a property of the action alone
- Meaning is a property of being referenced later

ACTION is permissionless  
MEANING is social + temporal

---

## 7) Failure Modes & Debug Checklist

### “Nothing happens when I witness”

- At least one ACTION must exist
- RESONANCE.ref must match a valid ACTION id
- UI should say: “Nothing to witness”

---

### “Resonance appears but nothing changes”

That is expected.

- v2.1 is not PoR
- No finalization exists
- Only reference attachment is shown

---

### “Import overwrote my ledger”

Import behavior must be explicit:

- Replace local ledger (simple)
- Or merge by TX id (better)

The UI must state which one is used.

---

## Closing

Memoria v2.1 is not a blockchain.
It is not a reputation system.

It is a **minimal experiential proof** of one idea:

**Meaning does not exist at the moment of action.
Meaning exists only when another mind later points at it.**
