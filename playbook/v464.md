- `ACTION` creation (with `intent + note`)
- `RESONANCE` attachment (`mode + RM amount`)
- Threshold `θ` and Finalization
- Optional time noise via `Next Turn` auto-witness

## 1) Concepts mapped to actual fields

### ACTION
Created by `commitAction()`:

- `type: "ACTION"`
- `id`
- `turn`
- `intent`
- `note`

### RESONANCE
Created by `attachResonance()`:

- `type: "RESONANCE"`
- `ref` (must point to ACTION id)
- `mode` (`witness / adoption / citation`)
- `rm` (user-entered resonance amount)
- `turn`

### FINALIZED
Created by `runFinalization()` when an ACTION passes threshold:

- `type: "FINALIZED"`
- `ref` points to the ACTION id
- `note` includes `RM>=θ`

### ref (the key)
`ref` is the edge connecting resonance/finalization back to a specific action.

If you remember only one thing:
> `ref` is how post-hoc meaning attaches.

---

## 2) The score model (as implemented)

Finalization checks:

For each action `a`:
- compute `score = rmFor(a.id)`
- finalize if `score >= θ`

`rmFor()` sums resonance contributions referencing that action:

- `witness` → weight `1`
- `adoption` → weight `1.5`
- `citation` → weight `2`

So:
- citation counts more
- adoption counts a bit more
- witness is baseline

---

## 3) Why “Finalize does nothing” sometimes
Because `score < θ`.

Example:
- `θ = 3`
- You attach resonance `RM=1` once (mode = witness)
- score = 1
- 1 < 3 → no finalization

That’s exactly why:

- set `RM=3` once → score becomes ≥ 3 → finalizes ✅

## 4) Buttons: what each does

### Commit Action
Adds one `ACTION` to ledger.

### Attach Resonance
Adds one `RESONANCE` referencing an action.
- `pick: latest` is easiest for controlled experiments
- `pick: random` is good for “worldline chaos”

### Next Turn ▶
- `S.turn += 1`
- 20% chance: auto-witness creates `RESONANCE` with `rm=1`
- else “quiet turn”

### Run PoR Finalization
- reads θ input
- scans actions
- appends `FINALIZED` txs for newly finalized actions

### Reset
Clears local toy state in the tab.
